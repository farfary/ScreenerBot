SECTION 5: COMPARISON DATA
================================================================================

COMPARISON: EPOCH-BASED vs HAZARD POINTERS

Dimension 1: Conceptual Complexity
  Epoch-Based: ⭐⭐⭐⭐ (Simple: Guard pattern)
  Hazard Ptrs: ⭐⭐⭐ (Complex: Per-pointer management)

Dimension 2: Cleanup Cost Complexity
  Epoch-Based: O(threads) - Linear in thread count
  Hazard Ptrs: O(threads × number_of_pointers)

Dimension 3: API Ease
  Epoch-Based: Very simple (Guard + Shared/Owned)
  Hazard Ptrs: More verbose, per-pointer tracking

Dimension 4: Per-Thread Overhead
  Epoch-Based: Low (~64 bytes per thread)
  Hazard Ptrs: Higher (hazard record per thread)

Dimension 5: Scalability
  Epoch-Based: Better with many threads (>4)
  Hazard Ptrs: Better with few pointer relations

COMPARISON: EPOCH-BASED vs RCU (Read-Copy-Update)

Dimension 1: Best Workload Type
  Epoch-Based: Mixed read/write workloads
  RCU: Heavy read workloads (95%+ reads)

Dimension 2: Cleanup Mechanism
  Epoch-Based: Automatic epoch advancement
  RCU: Grace period tracking

Dimension 3: Reader Complexity
  Epoch-Based: Readers must use guard
  RCU: Readers are trivial (no synchronization)

Dimension 4: Writer Complexity
  Epoch-Based: Straightforward
  RCU: Can be complex (requires copy-on-write)

COMPARISON: EPOCH-BASED vs GARBAGE COLLECTION

Dimension 1: Pause Times
  Epoch-Based: None (deterministic)
  GC: Variable (stop-the-world pauses)

Dimension 2: Predictability
  Epoch-Based: Highly predictable
  GC: Variable performance

Dimension 3: API Simplicity
  Epoch-Based: Requires learning (Guard pattern)
  GC: Completely transparent

Dimension 4: Memory Overhead
  Epoch-Based: Proportional to threads
  GC: Varies with heap size

Dimension 5: Best For
  Epoch-Based: Real-time, lock-free structures
  GC: General memory management

SECTION 6: KEY TECHNICAL CONCEPTS
================================================================================

EPOCH-BASED MEMORY RECLAMATION MECHANICS:

1. Core Concept
   - Time divided into discrete "epochs" (generation numbers)
   - Threads announce their current epoch
   - Memory freed when no active threads reference it
   - Non-blocking, deterministic cleanup

2. API Components (Rust implementation)

   Guard:
   - Represents thread's participation in current epoch
   - Created: let guard = pin()
   - Lifetime: Scoped to critical section
   - Dropped: Automatically on scope exit
   - Purpose: Ensures safe concurrent access

   Owned<T>:
   - Heap-allocated object owned by epoch system
   - Garbage collected when safe
   - Type-safe memory ownership
   - Automatic cleanup

   Shared<T>:
   - Atomic pointer to shared data
   - Load: Returns reference guarded by current Guard
   - Compare-and-swap: Atomic conditional updates
   - Safe concurrent access

   Atomic Operations:
   - Load: Read with guard protection
   - Store: Write to pointer
   - Compare-and-swap (CAS): Lock-free updates

3. Usage Pattern
   ```
   let guard = epoch::pin();           // Enter epoch
   let node = shared_ptr.load(Acquire, &guard);  // Read
   let value = unsafe { (*node).field };  // Access
   // Guard auto-dropped, exit epoch
   ```

SECTION 8: IMPLEMENTATION ALGORITHMS
================================================================================

ALGORITHMS COMMONLY IMPLEMENTED WITH EPOCH-BASED:

1. Treiber's Stack
   - Lock-free LIFO (Last-In-First-Out)
   - Single atomic pointer to head
   - Compare-and-swap for updates

2. Michael-Scott Queue
   - Lock-free FIFO (First-In-First-Out)
   - Atomic head and tail pointers
   - Sentinel node pattern

3. Harris's List
   - Ordered lock-free linked list
   - Supports search, insert, delete
   - Atomic mark-and-sweep deletion

4. Skip Lists
   - Probabilistic balanced search structure
   - Supports efficient search
   - Lock-free variant for concurrency

5. Hash Tables
   - Concurrent hash tables
   - Lock-free reads
   - Atomic updates with CAS

6. B+ Trees
   - Tree-based indexing
   - Concurrent variants for lock-freedom
   - Range queries and sorted iteration

7. Graph Structures
   - Concurrent graphs
   - Dynamic edge/vertex addition
   - Lock-free traversal

All require deferred memory reclamation to maintain safety.
